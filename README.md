Offline-first POCUS logbook scaffold for the web, with a path to bundled iOS and Android apps.

## Find your way around the code

- [`src/App.tsx`](./src/App.tsx) connects the main screens and coordinates app state.
- [`src/components/`](./src/components) contains the interface pieces, including case entry, case review, and the case list.
- [`src/hooks/`](./src/hooks) contains app behavior that is reused or easier to understand separately, such as loading local data, searching cases, backups, and printing.
- [`src/domain/`](./src/domain) contains case types and rules, backup validation, metrics, and print formatting. These files should not depend on the React interface or browser storage.
- [`src/domain/pathway-requirements.ts`](./src/domain/pathway-requirements.ts) is the versioned curriculum catalogue. It records sources, scan targets, supervision, case mix, scan-type quotas, and collection windows; current app support remains Heart and Lung.
- [`src/storage/`](./src/storage) reads and writes the on-device IndexedDB database and handles upgrades to saved data.
- [`src/styles.css`](./src/styles.css) contains the app layout and visual styles.

For a small first change, start with a label or layout in a component. If a change affects what a case means or how it is stored, check the domain model and backup validation as well. Database changes need an upgrade path so existing logbooks continue to open.

## Deploy a GitHub Pages test

The **Build and deploy Vite site to GitHub Pages** GitHub Actions workflow runs `npm run check` and publishes the production app when changes are pushed to `main` (or when the workflow is run manually). To enable it:

1. Push this project to a GitHub repository. If its default branch is not `main`, update the branch filter in `.github/workflows/deploy-vite-pages.yml`.
2. In the repository's **Settings → Pages**, choose **GitHub Actions** as the build and deployment source.
3. Push to `main` or manually run **Build and deploy Vite site to GitHub Pages** from the Actions tab. This workflow explicitly builds the Vite app and deploys `dist/`; do not run the separate `pages-build-deployment` workflow generated by GitHub.

The build automatically uses the correct base path for project pages and user/organization pages. For other static hosts, run `npm run check` and publish `dist/` over HTTPS.

GitHub Pages can make the app itself publicly reachable; site access controls depend on the GitHub plan and repository settings. The app does not upload or sync case data, but use only non-identifying test data on a hosted deployment. Generated backup files are excluded by `.gitignore`; keep them out of source control.

Browser storage is isolated by site origin. Cases saved at `localhost` will not appear automatically at the hosted address (or on another device). Before moving test data, download a backup from the current site and restore it on the destination site. Keep a separate copy of the backup; deleting browser site data or removing the app can permanently remove local cases.

## Logbook data

Lung and Heart cases are stored locally in this browser's IndexedDB; they are not uploaded or synced. Training targets can be hidden independently for each pathway without changing its saved cases.

Choose one pathway at a time from the **Logbook type** selector. The app has **Overview**, **Cases**, and **Metrics** pages for pathway progress, case history, and descriptive case patterns. Create or edit a case on its own screen; saving returns to the Cases page. Print, CSV, backup, and restore controls are on Overview.

Metrics currently summarize case activity over the last six months, recorded regions/views, findings marked Yes, image quality, impression categories, and management-impact markers. A choice between a rolling 12-month view and a calendar-year view is a requested future improvement, not yet available. Metrics describe only the data entered and do not assess competence. In development builds, **Preview sample data** displays generated cases in memory to help evaluate the metrics. Development builds also show **Admin test data** controls on Overview. On the hosted PWA, add `?admin=1` to the site address to reveal those controls. This query is only a convenience gate, not authentication. Populated synthetic cases are stored on this device, clearly labelled in the case list, included in backups, and can be removed without deleting real cases. Repeating population does not duplicate existing sample records.

Use **Export backup** to save a versioned JSON copy of all cases and pathway preferences. Web browsers download the file; native iOS and Android builds open the system share sheet so you can save it to a destination you choose. The app cannot confirm that a destination saved the file. Use **Restore backup** to merge a copy into this device: new case IDs are added, existing IDs and local preferences are kept, and repeated restores do not duplicate cases. Restore validates the whole file before saving it; files larger than 10 MB are not accepted. Backups from versions 1 and 2 are upgraded on restore. Restore does not replace or delete existing cases.

Use **Export CSV** to export the currently selected pathway for spreadsheet review. Web browsers download the file; native iOS and Android builds open the system share sheet. The export uses stable column names and pathway-specific findings, numbers cases by scan date, and omits internal IDs and timestamps. CSV quoting and spreadsheet-formula safeguards are applied. Free-text fields such as indication, diagnosis, summary, and reflection may still contain information you entered, so review them and remove patient-identifying details before sharing the file.

Backups are readable, unencrypted files and may contain everything entered in optional notes. Keep them somewhere private, and do not upload or email them to a shared service. The app does not yet connect to a home server or any other backup service. Clearing browser site data or removing the app can still remove locally stored cases, so save backups somewhere separate. Do not enter patient names, dates of birth, record numbers, or other identifying information. The case form warns about common patterns such as email addresses, phone numbers, labelled record numbers, and labelled dates of birth; it cannot reliably detect names or unlabelled identifiers. Review notes yourself and remove any patient-identifying details before saving. This is a personal training and reflection log, not a clinical record.

Cases can optionally be tagged with a normal, abnormal/pathology, or indeterminate impression and whether the scan changed management. These are personal review markers, not clinical advice or accreditation claims. Training mode shows total and directly supervised counts; with training targets hidden, the summary focuses on abnormal impressions and changed management.

Lung structured entry is organised by finding, with Yes and No choices and a single-line Not assessed checkbox for each region. New and untouched findings start as Not assessed; selecting Yes or No clears that checkbox. Existing Unable to assess (U/A) values remain supported in saved records. Case review and the printout continue to show results grouped by region.

Heart assessment findings use one-tap Yes, No, and Not assessed buttons. Existing Unable to assess values are presented as Not assessed in the form and remain supported in saved records.

Each case can be opened as a print-ready, single-page A4 report with **Print / PDF** from the Cases list. The compact table layout follows the structure of the official FUSIC logbook report forms without reproducing their logos or assessment branding. Use the browser or device print dialog to print it or choose **Save as PDF**. If the browser blocks the print window, the app shows an in-app print preview with its own print action. The sheet contains the case’s pathway-specific fields and leaves space for handwritten notes where optional reflections are blank.

From **Overview**, choose **Print logbook / PDF** for the selected pathway to create a multi-page training logbook. Its table follows the supplied logbook layout: study number, date, diagnosis, summary of main findings, and supervisor. It includes blank numbered rows up to the pathway reference and continues onto extra pages when there are more cases. This is a personal report using the fields recorded in the app, not an official FUSIC form or assessment document.

## Capacitor

The Capacitor configuration points to the local `dist/` directory. Build the web app before syncing native projects:

```sh
npm run build
npm run cap:sync
```

To create a native platform project for the first time:

```sh
npm run cap:add:ios
npm run cap:add:android
```

Native projects embed the built web assets. Do not add a remote `server.url` to the Capacitor configuration; the packaged app must not depend on downloading a hosted PWA at launch.
